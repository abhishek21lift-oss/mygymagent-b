# P4 Staff Rules + Bot Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Staff keyword rules + `#help/#stop/#start` bot answer chats before gym intents do.

**Architecture:** `AutoReplyRule`/`BotOptOut` tables; manager extracts group participants into `filer.fileGroup`; one `StaffReplyListener` (bot → opt-out → rules) runs on `whatsapp.received`, gym-intent listener stays as fallback guarded by a `MessageLog` check.

**Tech Stack:** NestJS 11, Prisma 6, BullMQ 6 (existing queues only), Next.js 16 + TanStack Query + RTL/Jest.

**Spec:** `docs/superpowers/specs/2026-10-08-p4-replies-design.md` (in `mygymagent-b`)

## Global Constraints

- 1 gym = 1 number; pacing + daily-limit + MARKETING-block unchanged.
- Replies go through `sendAdHoc` (`auto_reply.rule` / `auto_reply.bot`); recipient = sender (1:1) or groupJid (groups).
- No `--forceExit` in e2e; every spec keeps `afterAll: prisma.$disconnect + app.close`.
- Out of scope: regex tester UI, import/export, per-rule stats, RE2.

## Review Focus

- A group message from a phone-less LID sender → skipped, nothing sent, nothing crashed.
- A rule with an invalid regex → skipped with warn, other rules still answer.
- A `#stop` number gets no gym-intent answer either (opt-out is global).
- A message matching both a rule and a gym intent → exactly one reply.
- `#stop` inside a group chat → opts out that sender's phone everywhere.
