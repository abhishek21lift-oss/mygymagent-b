# Outgoing webhooks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Gyms register a URL + events + secret and receive signed JSON POSTs (n8n/Zapier) on 5 WhatsApp events with 3-attempt backoff retries.

**Architecture:** New domain events emitted at existing settle points; a dispatcher fans out to a new `wa-webhooks` BullMQ queue (attempts/backoff free from queue defaults + explicit per-job options); a processor POSTs with HMAC-SHA256 and an SSRF guard; CRUD + deliveries log API; settings card UI.

**Tech Stack:** NestJS 11, BullMQ 6, Prisma, Node 22 (global fetch, `AbortSignal.timeout`, `node:dns/promises`, `node:net` BlockList — no new deps), Next.js + TanStack Query.

**Spec:** `docs/superpowers/specs/2026-10-09-webhooks-design.md` (backend repo; implements it verbatim except the two committed amendments already in it).

## Global Constraints

- Node `>=22`; BullMQ 6 / `@nestjs/bullmq` 11 APIs only.
- `npx eslint` on touched files: 0 errors before every commit (prettier is enforced through it).
- Backend unit: `npx jest <path>`; e2e: `export REDIS_URL=redis://localhost:56379; npx dotenv -e .env.test -- npx jest --config ./test/jest-e2e.json --runInBand <spec>`.
- Frontend: `npx jest <hook-test>`, `npx tsc --noEmit`, `npx eslint <files>` — all clean.
- Every org-scoped mutation uses `updateMany`/`deleteMany` with `organizationId` (another org's id → 404, never 403).
- List caps: subscriptions `take: 100`, deliveries `take: 50` (clamped 1–200 like `broadcast.service.list`).
- Secrets: auto-generated, returned once at create/regenerate, never in GET.
- Delivery rows/logs never contain message bodies (status, counts, error text only).
- Migration agreement: `scripts/check-schema-drift.cjs` must print agree before commit.

## Review Focus

- Flapping receiver (500 then 200) → SENT on retry 2 with attempts=2. Pinned: T4 processor spec `recovers on retry`.
- `"*"` subscription receives all 5 events; `test` targets one sub only. Pinned: T4 dispatcher spec + T6 e2e.
- Unicode secret + unicode body → receiver recomputes the same hex over UTF-8 bytes. Pinned: T3 sender spec `unicode vector`.
- Sub deleted/disabled while jobs queued → zero POST, delivery FAILED `subscription removed`. Pinned: T4 processor spec.
- Private URL (e.g. `http://192.168.1.5/hook`) → 400 at save AND refusal at send with no retry. Pinned: T3 sender spec + T5 controller validation test.

## File Structure

- `src/whatsapp/webhook-events.ts` — event names, `matches()`, payload interface (pure).
- `src/whatsapp/webhook-sign.ts` — `signWebhook()` (pure).
- `src/whatsapp/webhook-ssrf.ts` — `assertPublicUrl()` (pure + dns).
- `src/whatsapp/webhook-send.ts` — `postWebhook()` + error classes (fetch).
- `src/whatsapp/webhook-dispatcher.service.ts` — `@OnEvent` fan-out, enqueues jobs.
- `src/whatsapp/webhook-delivery.processor.ts` — `@Processor`, delivery rows.
- `src/whatsapp/webhooks.controller.ts` — CRUD + test + regenerate + deliveries.
- `src/lib/hooks/use-webhooks.ts` + test, `src/app/(app)/settings/whatsapp/webhooks-card.tsx` (frontend repo).
