# P1 Rich-Send (image + reply) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Gym apne linked number se image-with-caption bhej sake existing `wa-send` queue se.

**Architecture:** Koi naya gateway/queue nahi. Sirf `WaSocket.sendMessage` payload union + `WaSendJob` me `mediaKey?`/`replyToMessageId?` add hoga; S3 `File` row se fetch karke Baileys ko passthrough.

**Tech Stack:** NestJS 11, Prisma 6, BullMQ 6 + ioredis, S3 (s3rver in test), Baileys 7rc (dynamic import), Next.js 16 frontend.

**Spec:** `docs/superpowers/specs/2026-10-08-wa-akg-merge-design.md`

## Global Constraints

- 1 gym = 1 number (`sessionIdFor(orgId)` = `gym-{orgId}`), no multi-session.
- MARKETING category refuse (403), daily-limit default 200 (429), 8–15s pacing via `WaSender.nextSlot`.
- `toJid()` country-code rule unchanged (Indian gym 10-digit → +91, else E.164 required).
- No `--forceExit` in e2e; every spec keeps `afterAll: prisma.$disconnect + app.close`.
- P1 = image + reply-quote only; NO poll/location/contact/react/star, NO video/audio/document, NO broadcast/cron.
- Zero Prisma migration in P1.

## Review Focus

- Cross-org `mediaKey` (dusre gym ki File key) → 400, kabhi fetch nahi.
- 10MB+ image → 400 enqueue se pehle, queue me junk nahi.
- Queue me pada message, bhejne se pehle number unlink → FAILED with plain reason.
- Non-image mime (pdf/mp4) P1 me → 400 "P1 me image only".
- Unknown `replyToMessageId` → send without quote (fail nahi, quote drop + warn log).
